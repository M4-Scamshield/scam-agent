# ScamShield 이슈 생성

사용자의 작업 메모를 사람이 읽기 쉬운 한국어 이슈 제목과 본문으로 정리한다. 초안 작성과 실제 등록 모두 같은 저장소 양식을 사용한다.

## 트리거

- 직접 호출: Codex의 `$scamshield-create-issue`, Claude Code의 `/scamshield-create-issue`.
- 자동 선택 예: ‘이슈 초안 작성해줘’, ‘이 작업 목록을 이슈로 정리해줘’, ‘이 내용을 GitHub 이슈로 등록해줘’.
- ‘이슈 템플릿을 수정해줘’, ‘PR을 작성해줘’는 [협업 템플릿 스킬](../scamshield-github-templates/SKILL.md)로 처리한다. 단순히 이슈를 조회·설명하는 요청에는 이 스킬의 생성 절차를 적용하지 않는다.

## 작성 기준 확인

- [README의 이슈·PR 안내](../../../README.md)와 관련 Issue Form을 읽는다. 기능·설계 변경은 [변경 제안 폼](../../../.github/ISSUE_TEMPLATE/change_proposal.yml), 결함은 [버그 폼](../../../.github/ISSUE_TEMPLATE/bug_report.yml)을 사용한다.
- 현재 구현에 관한 설명이 필요하면 [문서 인덱스](../../../docs/index.md)에서 관련 설계·아키텍처·change를 선택하고 실제 코드를 대조한다. 이슈 작성만으로 새 OpenSpec change나 서비스 구현을 시작하지 않는다.
- 사용자에게 받은 작업 항목을 빠짐없이 보존한다. 데이터 제공처, API, 실행 구조 등 정해지지 않은 선택은 미정으로 적고 완료된 기능처럼 설명하지 않는다.

## 일정한 제목과 본문

제목은 `type: 변경 내용`으로 쓴다. 기능 `feat`, 버그 `fix`, 문서 `docs`, 환경·관리 `chore`, 동작을 유지하는 구조 변경 `refactor` 중 내용에 맞는 종류를 고른다. 사용자가 지정한 형식이 있으면 그것을 우선한다.

기능·설계 변경 본문은 변경 제안 폼의 label을 제목으로 사용하며 다음 네 구역과 순서를 유지한다. 폼이 변경되면 그 label과 순서를 따른다.

1. **문제와 목표**: 현재 부족한 점과 이 작업이 만들 결과를 짧게 설명한다.
2. **변경 범위와 제약**: 요청받은 항목을 `- [ ]` 작업 목록으로 적는다. 완료 범위에 영향을 주는 제약·미정 사항만 덧붙인다.
3. **완료 조건**: 구현 여부를 확인할 수 있는 입력·동작·결과를 적는다. 작업명만 반복하지 말고 도구 선택, 결과 반환, 정보 부족 시 처리 등 확인할 행동을 구체화한다.
4. **관련 스펙과 작업 기록**: 실제 관련 문서·change·이슈만 연결한다. 없으면 ‘관련 기록 없음’으로 적는다.

버그는 버그 폼의 label과 순서로 관찰·기대 동작, 재현 절차, 환경, 근거를 정리한다. 없는 재현·검증 결과를 채워 넣지 않는다. 기능 이슈의 네 구역에 버그 정보를 억지로 맞추지 않는다.

필드명과 내부 구현 설명은 이슈의 범위를 이해하는 데 필요한 만큼만 쓴다. Mock 구현과 실제 외부 조회를 구분하고, 미정 사항을 설명 없이 Mock-only 완료 조건으로 축소하지 않는다. [Verify Agent 예시](references/verify-agent.md)는 기능 이슈 작성 시 참고할 수 있는 초안이며 모든 이슈에 적용할 필수 범위가 아니다.

## 실제 GitHub 등록

‘초안 작성’, ‘형식 정리’, ‘스킬 만들기’는 로컬 작성으로 끝낸다. 사용자가 ‘이슈 생성·등록·올리기’를 요청했다면 그 권한으로 등록까지 진행하며 이미 받은 허락을 다시 묻지 않는다.

등록할 때는 다음을 확인한다.

- Git remote와 사용자 지정 저장소를 대조해 대상 저장소를 확정한다. 중복될 만한 기존 이슈의 제목·본문·상태를 확인한다. 사용자가 기존 이슈 수정을 요청한 경우에만 그 이슈를 수정한다.
- 지원되는 GitHub 연결 도구를 사용하거나, `gh issue create --repo OWNER/REPO --title "type: 변경 내용" --body-file PATH`로 등록한다. 본문 파일은 UTF-8과 실제 줄바꿈을 유지한다. `gh`가 없다면 사용 가능한 인증된 GitHub 도구/API를 사용하고, 인증이 없으면 완성된 초안과 등록하지 못한 이유를 전달한다.
- label·담당자·milestone은 사용자가 지정했거나 저장소에 적용할 근거가 있을 때만 설정한다. API 키나 개인 통화 내용을 이슈에 넣지 않는다.
- 생성 응답의 URL과 실제 제목·본문을 확인한다. 시간 초과 등으로 성공 여부가 불명확하면 먼저 이슈 목록을 확인하고, 확인 없이 같은 생성 요청을 반복하지 않는다.
- 사용한 임시 본문 파일을 정리한다. 관련 작업 기록이 있다면 [문서 동기화 스킬](../scamshield-docs-sync/SKILL.md)에 따라 실제 등록 URL과 상태를 반영한다.

초안 요청에는 제목·본문을, 등록 요청에는 확인된 이슈 URL과 주요 미정 사항을 간결하게 전달한다.
