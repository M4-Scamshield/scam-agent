# feat: Verify Agent와 검사·사건번호·전화번호 조회 도구 구현

아래 본문은 사용자가 제공한 네 작업을 같은 형식으로 정리한 예시 초안이다. GitHub에 등록된 이슈나 확정된 외부 조회 계약을 뜻하지 않는다.

## 문제와 목표

현재 데모의 Verify 역할은 사건번호 Mock 조회 요청을 선택한다. 통화 상대방이 제시한 검사 신원, 사건번호, 전화번호를 확인할 수 있도록 Verify Agent와 조회 도구를 구현한다.

## 변경 범위와 제약

- [ ] 검사 실존 여부 파악 도구 구현
- [ ] 사건번호 조회 도구 구현
- [ ] 전화번호 조회 도구 구현
- [ ] Verify Agent를 위한 시스템 프롬프트 작성 및 연결

조회 데이터 제공처와 접근 방식, 각 도구의 입력·결과 형식은 구현 전에 정한다. Mock 검사와 실제 외부 조회의 완료 범위를 구분한다. 현재 Graph의 도구 선택·실행 분리와 turn당 1회 조회 한도를 바꿔야 한다면 이유와 변경 범위를 별도로 정리한다.

## 완료 조건

- 통화에 제시된 정보에 맞춰 세 조회 도구 중 필요한 도구와 인자를 선택할 수 있다.
- 각 도구의 조회 성공, 미조회 대상, 조회 실패를 구분해 반환하고 결과를 통화 상태에 반영할 수 있다.
- 정보가 부족하면 인자를 만들어 조회하지 않고, 추가로 확인할 정보를 안내한다.
- 시스템 프롬프트에 Verify 역할, 도구 사용 기준, 조회하지 않은 결과를 만들지 않는 원칙이 포함된다.
- 대표 입력과 정보 부족·조회 실패 사례를 검증하고, 실제 외부 조회의 실행 근거와 미검증 항목을 기록한다.
