# 면접 사칭 사기 통화 합성 데이터

사용자 요청에 따라 만든 한국어 면접 상황의 1대1 사기 통화 100건이다. 실제 통화의 전사문이 아니며, 사람 100명이 각각 작성한 독립 대본도 아니다. 작성한 20개 사기 시나리오·100개 경력 사례·면접 문답·5개 반응을 고정 시드로 조합한다. 발표 PPTX는 제공되지 않아 내용을 확인하지 못했다.

## 파일

- `interview_phishing_100.json`: 정답과 화자 역할을 포함한 원본 JSON.
- `interview_phishing_inputs.json`: 평가 입력만 포함한 JSON으로 화자는 A/B이며 정답·사기 유형·위험 구간을 제외한다.
- `validation_report.json`: 실제 파일을 읽어 집계한 수량·길이·화자·중복·유형 분포.
- [생성·검사 도구](../../experiments/build_interview_dataset.py): 표준 라이브러리만 사용하며 외부 API를 호출하지 않는다.

## 형식과 사용

원본 최상위는 `metadata`, `calls` 객체다. 통화의 `utterances`에는 시간순으로 `sentence_id`, `speaker`, `text`가 있다. `speaker`는 정확히 `나` 또는 `피싱범`이다. 한 항목에 종결 부호 하나로 끝나는 한 문장을 넣어 **문장 수 = 발화 항목 수**로 정의한다. 같은 사람이 연속으로 말할 수 있다. 타임스탬프·음성·STT 결과는 포함하지 않는다.

`annotations`의 사기 유형과 `evidence_sentence_ids`는 합성 시나리오 작성 기준이다. `first_evidence_sentence_id`는 명시적인 사기 요구가 처음 등장하는 위치이지, 그 전까지 사기 가능성이 없다는 뜻이나 실제 모델의 탐지 시점은 아니다. `outcome`은 통화 끝에서 지원자가 취한 행동이며 실제 피해 발생을 보증하지 않는다. 회사명·지원자 설정과 대화 내용은 허구다. 실사용 가능한 계좌·인증번호·연락처·악성 링크는 넣지 않는다.

모델에는 `interview_phishing_inputs.json`의 `utterances`만 전달하고, `call_id`로 원본 정답과 결합한다. 정답 역할명이나 주석을 프롬프트에 넣지 않는다. A/B 중 누가 지원자인지는 통화별로 바뀐다. JSON의 `speaker` 값을 역할로 간주하지 않는다.

```sh
python3 experiments/build_interview_dataset.py
python3 experiments/build_interview_dataset.py --check
```

같은 버전의 생성 도구는 같은 파일을 재생성한다. `--check`는 데이터셋을 수정하지 않고 검사하며 실패 시 0이 아닌 종료 코드를 반환한다. 데이터셋에 맞춘 JSON 구조와 불변조건을 검사하고, 대화의 사실성이나 탐지 성능을 자동으로 증명하지는 않는다.

실제 생성 결과는 100통화·7,451문장으로 통화당 평균 74.51문장이고, 50~100의 51가지 길이를 모두 포함한다. 20개 사기 유형마다 5통화이며 100개 직무와 20개 분야를 사용한다. 최초 명시적 사기 근거는 11~77번째 문장에서 등장한다. 완전히 같은 통화나 한 통화 안의 동일 문장 반복은 없다. 전체 고유 문장은 2,343개로 31.45%이며 나머지에는 다른 통화와 공유하는 문답이 있다.

## 평가 범위

이 파일의 100건 모두 사기 통화이므로 단독으로는 사기 재현율과 문장 단위 최초 경고 위치를 평가할 수 있다. 오경보율·특이도·ROC AUC에는 정상 표본이 필요하다. 후속 사용자 요청으로 [정상 면접 100건과 혼합 200건 평가셋](../interview_normal/README.md)을 추가했고 Plan1 실제 평가는 별도로 기록한다. 길이를 초 단위로 변환하지 않았으므로 경고 시간도 문장 위치로만 비교한다.

같은 시나리오·문답을 공유하는 합성 데이터이므로 학습/평가를 무작위 통화 단위로 나누면 누출 위험이 있다. 우선 평가 전용으로 사용하고, 학습에도 사용할 때에는 사기 유형과 문답 원형을 분리한 별도 대본을 준비한다. 실제 음성·ASR 오류·화자 분리 오류와 사람 간 자연스러움은 별도 검증이 필요하다.

변경 근거와 검사 기록은 [work](../../openspec/changes/interview-phishing-dataset/work.md)에 있다.
