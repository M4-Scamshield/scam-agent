# Jev 단독 탐지 성능 실험 계획

관련 이슈: [#9 feat: Jev 단독 탐지 성능 실험](https://github.com/M4-Scamshield/scam-agent/issues/9)

## 배경·목적

Jev는 현재 2AS Graph에서 Gemini 앞단 탐지기로만 호출되고, 탐지 성능 자체를 측정한 적이 없다. 라벨된 한국어 통화 데이터로 **Jev 단독 보이스피싱 탐지 성능**을 측정하고, 판단 방식(단일 종합 vs 카테고리 분할)에 따른 성능 차이를 비교한다.

## 공통 설정

- **모델**: Jev(TypeSafe System One) 단독. Gemini·Graph 미사용. `scamshield.jev.JevClient`의 호출 방식을 재사용한다.
- **입력 단위**: 전체 통화 transcript를 1회 호출로 판단(기본). turn 누적 호출은 후속. — *확정 필요*
- **데이터**: 사용자가 직접 준비한다. 형식(JSONL/CSV) 확정 후 로더를 맞춘다. `experiments/data/`는 git에서 제외(개인정보·통화 원문 비커밋).
- **운영 제약**: TLS 가로채기 환경에서 `truststore` 주입 필요. API 한도(429) 발생 시 지연/재시도로 완화하고, 호출 실패 건은 지표와 분리해 집계한다. 키·원문·오류 본문을 출력·커밋하지 않는다.
- **양성(positive) 클래스** = `Yes`(보이스피싱).

## 평가 지표 (두 Plan 공통)

2×2 Confusion Matrix를 표로 그린다.

|  | 예측 Yes | 예측 No |
|---|---|---|
| **실제 Yes** | TP | FN |
| **실제 No** | FP | TN |

- **Accuracy** = (TP + TN) / (TP + TN + FP + FN)
- **Precision** = TP / (TP + FP)
- **Recall** = TP / (TP + FN)
- (선택) F1 = 2 · P · R / (P + R)
- 호출 실패·한도 초과 건수는 지표 계산에서 제외하고 별도로 표기한다.
- (선택) P(Yes) 분포와 임계값(threshold) 분석.

## Plan 1 — 단일 종합 판단 (baseline)

- 기존 Jev 호출 방식 그대로: 전체 transcript를 한 번에 주고 `voice_phishing`의 Yes/No와 P(Yes)를 받는다.
- 각 샘플의 verdict를 정답 라벨과 비교해 Confusion Matrix·지표를 산출한다.
- 목적: 이후 비교의 **기준선(baseline)** 확보.

## Plan 2 — 카테고리 분할 (Divide & Conquer)

- **아이디어**: 하나로 종합 판단하는 대신, 보이스피싱 정황을 여러 카테고리로 나눠 각각 Jev가 Yes/No·확률을 판단하고, 그 결과를 통합해 최종 verdict를 만든다. 판단을 세분화하면 성능이 오를 것이라는 가설.
- **평가**: 데이터 라벨이 전체 Yes/No만 있으면 **최종 통합 verdict**를 라벨과 비교해 Plan 1과 같은 지표로 평가한다. 카테고리별 출력은 분석용으로 로깅한다. (데이터에 카테고리별 정답 라벨이 있으면 카테고리별 지표도 산출 가능 — 데이터 스키마에 따라 결정)

### 카테고리 (확정 — 4개)

Jev 지침(`scamshield/jev.py`의 보이스피싱 지표: 기관 사칭, 범죄 연루 협박, 안전계좌 송금, 비밀번호/인증번호 요구, 원격제어 앱 설치·비밀 유지)을 기반으로 확정한다. 각 카테고리는 **독립적인 Yes/No·확률 질문**으로 판단하며 상호배타적이지 않다(한 통화가 여러 카테고리에 Yes일 수 있다).

1. **공공기관·금융기관 사칭 여부** — 검찰/경찰/금감원/은행 등 사칭
2. **심리적 압박·협박 여부** — 범죄 연루 빌미, 긴급성 강조, 비밀 유지 강요
3. **금전·자금 이체 유도 여부** — 안전계좌 송금, 대출 상환 선입금 등
4. **개인정보·인증수단·원격제어 요구 여부** — 비밀번호/OTP 요구, 원격제어 앱 설치

### 통합 방식 — B. 임계 개수 (채택, 세부는 추후 확정)

4개 카테고리 중 **Yes로 판정된 카테고리가 k개 이상이면 최종 Yes**로 통합한다.

- 실험에서는 k를 1~4로 바꿔가며 각각의 Confusion Matrix·지표를 산출하고, 결과를 보고 최종 k를 정한다(`k=1`은 OR 규칙과 동일).
- 최적 k 선택 기준(정밀도·재현율 trade-off)은 결과를 본 뒤 논의한다.
- 대안(확률 통합 C, 학습 기반 결합 D)은 후속 비교 대상으로 남겨둔다.
