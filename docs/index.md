# 프로젝트 문서 안내

이 파일은 요청에 필요한 **문서 종류와 읽기 시작점**을 고르는 최상위 인덱스다. `docs/`의 문서를 목적에 따라 안내하고, 변경별 문서가 있는 `openspec/`으로 연결한다.

## 필요한 문서로 이동하기

확인하려는 내용에 맞는 진입점을 선택한다. 폴더의 인덱스로 이동한 뒤, 그 안의 문서 목록과 내용 설명을 보고 필요한 본문을 읽는다.

| 확인하려는 내용 | 진입점 | 그곳에서 찾을 자료 |
|---|---|---|
| 프로젝트 목적과 합의된 MVP 범위 | [프로젝트 컨텍스트](project-context.md) | 사용자 제공 방향, 확정 사항과 미정 사항 |
| 시스템 구성과 현재 구현 범위 | [아키텍처](architecture/index.md) | 구성·책임 경계·데이터 흐름, 현재 구현과 설계 방향의 구분 |
| 구현할 구조와 동작의 상세 기준 | [상세 설계](design/index.md) | 주제별 설계 문서와 각 문서가 다루는 계약·동작 |
| 선택의 이유와 결정 상태 | [설계 결정](decisions/index.md) | 채택한 선택·대안·근거, 제안과 확정의 구분 |
| 조사와 실험의 근거 | [분석](analysis/index.md) | 조사 결과·재현 절차·조건·한계 |
| 특정 변경의 요구사항과 진행 기록 | [OpenSpec](../openspec/index.md) | 관련 change의 proposal·spec·design·tasks·work |
| 에이전트의 작업과 문서 관리 방법 | [Harness](harness/index.md) | 공통 작업 절차·문서 관리 규칙·양식·스킬 |

## 인덱스를 사용하는 방법

세부 설계 주제와 문서별 내용 설명은 각 폴더의 인덱스에서 관리한다. 예를 들어 LangGraph나 Jev 설계를 찾을 때는 위의 상세 설계 진입점에서 시작해 해당 문서를 선택한다. 구조·계약·기능 동작의 설명은 연결된 본문에 작성한다.

변경 작업을 이어갈 때는 OpenSpec 인덱스에서 관련 change를 찾고 진행·검증 기록을 확인한다. change에서 연결한 상위 설계와 기준 문서를 따라가면 변경의 근거를 확인할 수 있다. 문서 종류나 진입점이 달라지면 이 파일을, 세부 문서가 추가되면 해당 폴더의 인덱스를 갱신한다.
