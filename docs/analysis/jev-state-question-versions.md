# Jev 상태 질문 버전별 변경 이력

Jev에 보내는 상태 질문 F1~F6의 문구와 평가 정답을 버전마다 어떤 문제 때문에 바꿨는지 정리한다. 각 버전의 실제 실행 결과와 커밋도 함께 남긴다. 설계와 진행 기록은 [jev-state-agents change](../../openspec/changes/jev-state-agents/work.md)에 있고, 상태 정의의 현재 기준은 [spec](../../openspec/changes/jev-state-agents/spec.md)이다.

## 확인 방법

- 스크립트: [probe_states.py](../../experiments/jev_states/probe_states.py)
  - 상태 질문 6개와 기존 `voice_phishing` 질문을 한 요청으로 보낸다.
  - 통화마다 전체 대본을 한 번 보낸다. 발화 시점별 감지는 재지 않는다.
- 표본: KorCCVi 사기 15통화와 정상 5통화
  - 사기 통화는 판단불가를 빼고 3,000자 이하에서 뽑는다.
  - seed 0은 v1~v3에서 같은 20통화를 썼고(`--same-as`), seed 1은 이와 겹치지 않는 새 20통화다.
- 정답: KorCCVi LLM 라벨을 F로 다시 묶은 통화 단위 존재 여부다. 사람 검수는 하지 않았다.
- 결과 파일에는 call_id, 정답, 상태별 판단·확률, 지연, 토큰만 있다. 대본은 없다.
- 아래 표의 v1~v4는 모두 **현재 정답**(묶음 수정, F5 N7 제외, F4 N5·N6 좁힘을 반영한 정답)으로 다시 채점했다. 그래서 당시 work 기록의 수치와 다를 수 있다.
- Jev 응답은 문구를 바꾸지 않은 질문도 실행마다 조금 달라진다. 1~2건의 차이는 변동일 수 있다.

## 버전별 문제와 변경

### v1 — 처음 작성 (2026-11-16)

- 질문: 공통 지시("사기인지 판단하지 말고 행동이 나타났는지만 판단")와 상태별 Yes/No 기준을 둔다.
- 확인한 것: 질문 7개를 한 요청에 보내도 받는다(20/20 성공). 지연 중앙값은 0.23초였다.
- 문제
  - F6 미탐 대부분이 대출빙자 통화의 금융회사 자기소개였다. v1 F6(권위 사칭)은 전화 조사·녹취 같은 절차 연출만 Yes로 보고 "소속만 밝히면 No"였다.
  - F5 미탐은 의심 무마(N7)와 할 말 지시(N9)였다. v1 F5(고립)에는 의심 무마가 없었고, 할 말 지시는 은행원·가족에게 할 거짓말로만 좁게 있었다.
  - v1 F5 No에는 "통화 품질 때문에 조용한 곳을 권함"이 있었다. 이 문구는 v3까지 그대로 남았다.

### v2 — F5·F6 정의 확대 (2026-11-16)

- 변경
  - F5 "고립"을 "고립·의심 차단"으로 바꿨다. 할 말 지시, 직접 확인 막기, 의심 무마를 넣었다.
  - F6를 "권위·절차 연출"로 바꿨다. 기관·회사명과 직함으로 자기소개, 규정·공문 언급, 정부 지원 상품 내세움을 넣었다.
- 결과: F5 재현 2/4→4/4, F6 8/12→12/12. 문구를 바꾸지 않은 F2·F3도 결과가 조금 달라졌다(실행 변동).
- 상태별 FN·FP를 대본에서 하나씩 확인해 원인을 Jev 미탐·정의 차이·묶음 오류·정답 누락·경계로 나눴다. 자세한 표는 [work](../../openspec/changes/jev-state-agents/work.md#상태별-미탐오탐-원인-v2)에 있다.
- 문제
  - **묶음 오류:** [group_new.py](../../experiments/korccvi_tactics/group_new.py)가 N2의 `일당`을 급여 뜻의 일당에도 걸었고, `연체`·`기존 대출`이 이득 약속 라벨을 N4로 끌어갔다. F2·F4·F6 정답이 틀렸다.
  - **F2 사기 FP 3:** "이 통장을 직접 개설했나"라는 추궁을 Jev가 정보 캐기로 봤다. 정답은 이를 F4(연루 연출)로 셌다.
  - **F4 FN:** 선입금 조건이 없는 저금리 제안을 정답(N6)은 F4로 셌다. spec F4는 "돈을 먼저 내는 조건의 혜택"만 Yes다.
  - **F5 경계:** 의심에 둘러대거나 안심시키는 말(N7)이 F5인지 정하지 않았다.

### 정답 수정 — KorCCVi 묶음 오류 (2026-11-16)

- N2 규칙을 범행 일당 뜻으로 좁혔다. 이득 약속 라벨 5개는 `OVERRIDES`로 N6에 넣었다.
- 수정 전후 라벨 1,605개를 대조했고, 바뀐 라벨은 의도한 6개뿐이다.
- 정규식을 넓게 고치는 방법도 시험했지만 맞게 묶여 있던 라벨 13개가 같이 바뀌어 쓰지 않았다.
- F 출현율: F2 35.6→35.3%, F4 78.1→79.0%, F6 83.4→83.0%. [KorCCVi 분석](korccvi-scam-tactics.md)에 반영했다.

### v3 — 상태 경계 정의 (2026-11-16)

- 변경(사용자 결정)
  - F2 No: 사건에 나온 계좌를 직접 만들었는지 추궁만 하는 경우. 이는 F4다.
  - F4 No: 선입금 조건이 없는 저금리·대출 제안
  - F5 No: 의심에 해명하거나 안심시키기만 하는 경우. 평가 정답에서도 F5는 N7을 빼고 센다.
- 결과(seed 0): F2 사기 FP 3→0, F5 사기 FP 2→1. spec 정의 기준으로 Jev가 놓친 것은 F4 연루 통보 1건(0.46)이다.
- 남은 문제: F4 FN 4건은 선입금 없는 저금리 제안이다. spec으로는 No가 맞지만 정답 N6이 이를 F4로 센다. N6을 나눌지는 아직 정하지 않았다(2026-11-18 정답 수정에서 정함).

### v3 새 표본 확인 (2026-11-17)

- 같은 20통화로 문구를 고쳤으므로, 겹치지 않는 seed 1로 v3를 그대로 돌렸다.
- 유지된 것: F1·F4·F6. spec 정의 기준 Jev 미탐은 0이다. F2의 계좌 개설 추궁 FP는 나오지 않았다.
- 문제
  - **F5 재현 3/7:**
    - 3건은 녹취 증거를 핑계로 제3자 목소리를 막거나 조용한 곳으로 옮기게 했다. v1부터 있던 F5 No의 "통화 품질 때문에 조용한 곳을 권함"이 사기범의 핑계와 그대로 겹쳤다. seed 0에는 이런 통화가 적어 드러나지 않았다.
    - 1건은 IP 추적을 핑계로 메신저·인터넷 사용을 막고 답장 전 보고하게 했다. F5 Yes 목록에 연락 차단이 없었다.
  - **F3 사기 FP 4:** 2건은 사람 없는 곳·조용한 곳으로 가게 한 경우다. F5 행동이 F3의 "특정 장소 이동"에도 걸렸다. 1건은 출석 요구(소환 위협에 가까움), 1건은 은행으로 가게 한 정답 누락이다.
  - F3 정상 Yes 2: 상담원이 담당 부서 번호를 안내했다. seed 0과 같은 유형이고, 에이전트가 거르기로 했다.
  - F2 FN 2, F4 FN 1은 정의 차이(생년월일 확인, 인터넷뱅킹 사용 여부, 조사 질문)이고, F4 FP 2는 정답 누락이다.

### v4 — F5 차단 행동과 F3 장소 이동 경계 (2026-11-17)

- 변경(2026-11-17 사용자 결정)
  - F5 Yes: 녹취·통화 품질을 핑계로 제3자가 듣지 못하게 하거나 혼자 있게 함, 메신저 등 다른 사람과의 연락을 막음
  - F5 No: "조용한 곳을 권함"을 빼고 "해명·안심만 함"만 남김
  - F3 장소 이동: 은행·지점·만날 장소처럼 거래나 대면이 일어나는 곳만 Yes. 혼자 있는 곳·조용한 곳은 F5
- 두 표본 모두 이전과 같은 통화로 실행했다. 실패는 0이다.
- 결과
  - **F5:** seed 1 재현 3/7→6/7. 녹취 핑계 차단 3건과 연락 차단 1건을 모두 잡았다. seed 0 사기 FP는 1→0이고, 정상 통화 F5 Yes는 두 표본 모두 0이다. F5를 넓혀도 정상 오탐은 늘지 않았다.
  - **F3:** seed 1 사기 FP 4→3. 사람 없는 곳으로 가게 한 1건은 No가 됐다. 그러나 조사를 받으러 조용한 곳으로 옮기게 한 통화는 여전히 F3 Yes(0.89)이고 F5는 No(0.02)다.
  - 남은 F3 사기 FP의 나머지 2건은 은행으로 가게 한 정답 누락과 출석 요구다. seed 0에서는 다른 곳에 대출을 문의해 보라는 말이 F3 Yes(0.54)가 됐다(경계).
- 문구를 바꾸지 않은 질문의 변동
  - 기준값 0.5 근처의 판단이 뒤집혔다. F2 1건(0.50→0.46), F4 1건(0.50→0.46), F6 1건(0.51→No), F1 정상 1건(0.49→0.50)이다.
  - 이 차이는 문구 변경의 효과가 아니라 실행 변동으로 본다.
- 남은 문제
  - 조사를 핑계로 조용한 곳으로 옮기게 하는 행동을 Jev는 F3 장소 이동으로 본다. F3 No에 넣은 문구만으로는 바뀌지 않았다.
  - F4 FN 중 선입금 없는 저금리 제안(seed 0 4건)과 조사 질문(seed 1 1건)은 정답 묶음(N6, N5)이 spec보다 넓어서 생긴다(2026-11-18 정답 수정에서 정함).

### 정답 수정 — F4의 N6·N5 (2026-11-18)

- 문제: 정답의 F4는 N6(보상·혜택 약속)과 N5(분실·개설·양도 여부 추궁)를 통째로 센다. spec F4는 돈을 먼저 내는 조건의 혜택과 혐의 추궁만 Yes다. 그래서 seed 0 F4 FN 5건 중 4건과 seed 1 FN 1건이 Jev 미탐이 아니라 정의 차이였다.
- 라벨만으로는 나눌 수 없었다.
  - N6 라벨은 "저금리 대출 약속"처럼 선입금 조건이 라벨에 드러나지 않는다. 조건은 같은 통화의 돈 요구에서 드러난다.
  - N5 라벨에는 혐의 추궁(통장 판매·양도 여부, 가해자인지 가림)과 전화 조사(신분증 분실·정보 유출 경위)가 섞여 있다.
- 변경(사용자 결정, [probe_states.py](../../experiments/jev_states/probe_states.py)의 `gold_of`)
  - N6은 같은 통화에 송금·납부 요구(R1)가 있을 때만 F4로 센다.
  - N5는 라벨에 판매·양도·가해자·피의자·공모·개설 같은 혐의 추궁 표현이 있을 때만 센다. 분실·유출 경위 질문과 입증 절차 안내는 세지 않는다. spec은 전화 조사를 F6로 본다.

- 해석: 창 방식은 재현을 잃지 않고 "같은 상태가 다시 나왔는지"를 Jev 응답만으로 알 수 있게 한다. 남은 문제는 반복 호출 수이고, 정상 통화의 F3·F6은 창 방식에서도 켜지므로 여전히 LLM이 걸러야 한다.
