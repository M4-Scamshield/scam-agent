# 새 면접 대본으로 Jev 재평가

평가일: 2026-11-14. 대상: 기존 문답을 복사하지 않은 합성 면접 장면 100건(사기·정상 각 50건). 사용자는 기존 합성 200건의 100% 결과를 의심해 다른 데이터로 재평가하도록 요청했고, 면접 상황의 새 합성 대본으로 범위를 명시했다. 실제 통화 KorCCVi로 대체하지 않았다.

## 이전 100% 감사

[기존 평가](interview-phishing-dataset.md)의 200개 예측을 다시 집계해 TP 100·TN 100·FP 0·FN 0을 확인했다. 당시 run_manifest에 기록된 원본·평가 입력·정답·CSV·Plan1/common/생성기/시각화 도구의 해시도 모두 일치했다. Plan1은 CSV의 정답을 채점에만 쓰며 모델에는 transcript 문자열만 전달한다. 정답 역할명·파일명·ID가 모델 입력에 들어간 흔적은 확인되지 않았다.

Plan1에는 모델 학습이나 미세조정 단계가 없다. 따라서 ‘학습 데이터와 시험 데이터가 같아서 나온 100%’라고 단정할 근거는 없다. 확인한 문제는 합성 사례 구성과 대표성이다. 기존 정상·사기 100쌍의 같은 위치 발화를 비교하면 문장이 평균 **64.27%** 일치한다(쌍별 49.02~76.00%). 기존 분석에도 정상·사기 모두 반복 문답과 명확한 정상 절차 설명을 사용한다고 기록돼 있다. 이 점은 쉬운 평가셋일 가능성의 근거이며 100%의 원인을 실험적으로 분리해 입증한 것은 아니다.

별도로 저장된 과거 KorCCVi Plan1 예측 2,927건도 재집계했다. TP 536·FN 159·FP 0·TN 2,232로 정확도 94.57%·재현율 77.12%였다. 이번 새 대본 실험의 일부가 아니고, 데이터·길이·시점이 달라 직접적인 대조군도 아니다.

## 새 평가의 고정 조건

- [새 원본과 사용법](../../datasets/interview_holdout/README.md): 직접 작성한 100개 대화, 총 960발화. 기존 문답 조합 생성기를 사용하지 않는다.
- 사기·정상 각각 8발화 20건·10발화 20건·12발화 10건, 면접관 A/B 각 25건. 모델 입력은 중립 화자와 대화 본문뿐이다.
- 계정 접근·과제 결제·장비·보험·급여·인증 등을 악용하는 장면과 같은 소재를 다루는 정상 면접을 포함한다. 정상 중에는 사기 대응을 묻는 역할극·직무 질문도 있다.
- 중복 검사: 기존 200건과 같은 전체 대화 0건, 정규화 후 15자 이상 발화 정확 일치 0건, 새 대본끼리 긴 발화 반복 0건. 의미적으로 새로운 수법만으로 구성했다는 뜻은 아니다.
- 대본·정답·입력·코드 해시를 API 호출 전에 동결했다. 동일 Plan1·동일 프롬프트·동일 choice Yes/No 규칙으로 각 대화 전체를 1회 전송했다. 임계값을 선택하거나 결과 확인 뒤 데이터를 바꾸지 않았다.
- 설정 별칭 `jev-latest`. 기존 어댑터가 응답의 model을 보존하지 않아 정확한 모델 버전은 알 수 없으며 이전 평가일과 같은 버전이라고 보장하지 않는다.

## 결과

| 실제 / 예측 | 사기 Yes | 정상 No |
|---|---:|---:|
| 사기 50건 | 50 (TP) | 0 (FN) |
| 정상 50건 | 2 (FP) | 48 (TN) |

| 지표 | 결과 |
|---|---:|
| 성공 / 실패 | 100 / 0건 |
| 정확도 | 98.00% |
| 정밀도 | 96.15% |
| 사기 재현율 | 100.00% |
| F1 | 98.04% |
| 특이도 / 정상 오경보율 | 96.00% / 4.00% |

평균 왕복 지연은 약 0.229초, 입력 71,798토큰·출력 3,400토큰이다. 단가를 지정하지 않아 금액은 계산하지 않았다. 예측 CSV를 별도 정답과 ID별 재대조하고, 혼동행렬을 Plan1과 독립적으로 재집계했다. 실행 전 해시와 실행 후 파일도 모두 일치했다.

이항 표본이라고 가정한 Wilson 95% 구간은 정확도 약 93.00~99.45%, 사기 재현율 약 92.87~100.00%다. 다만 이 대본들은 실제 통화를 무작위 추출한 표본이 아니므로 이 구간을 실사용 모집단 신뢰구간으로 해석하지 않는다.

## 오탐 두 건

| 평가 ID | 상황 | P(Yes) |
|---|---|---:|
| holdout_049 | 금융 상담원 면접에서 안전계좌 사기 피해 고객 대응을 질문 | 0.99 |
| holdout_095 | 인사 면접에서 채용 사기 제보 처리 방법을 질문 | 0.71 |

두 건 모두 현재 면접의 당사자가 지원자에게 돈이나 인증정보를 요구하지 않는다. 제삼자의 사기 사례에 관한 면접 질문을 현재 통화 자체의 사기로 해석했을 가능성이 있다. 모델이 판단 이유를 반환한 것은 아니므로 이는 원문과 예측으로부터의 해석이다. 사전 정답은 **현재 면접 통화의 사기 여부**를 기준으로 했다. 기존 프롬프트의 ‘통화에 보이스피싱을 의심할 정황’이라는 표현은 사기 사건을 논의하는 대화에도 적용될 여지가 있어, 평가 목표와 프롬프트 해석의 경계 문제도 남는다.

현재 데이터에서 표현을 바꾸거나 해당 두 건을 제외해 점수를 다시 만들지 않았다. 상세 내용은 [오류 사례](../../experiments/Plan1-JevOnly/results/interview_holdout_100/error_cases.md)에 있다.

## 해석과 후속

이번 새 대본에서는 전체 정확도가 100%에서 98%로 달라졌지만 사기 재현율은 여전히 50/50이었다. 이 결과로 현실적인 사기 미탐 위험까지 충분히 검증했다고 판단하지 않는다. 작성자가 사기 의도를 알고 만든 대본에는 자금·권한을 넘기라는 뚜렷한 요구가 있고, 정상에도 절차를 확인하는 표현이 있어 합성 작성 편향이 남는다.

새 대본은 이전 200건과 별도이지만 같은 에이전트가 작성·라벨링했으며 수법과 안전 절차 일부는 겹친다. 독립 작성자·사람의 라벨 합의·실제 통화·음성인식 오류·모델 사전학습 미포함·반복 측정은 확인하지 않았다. 표본 수(200→100), 통화 길이(50~100문장→8~12발화), 사례 구성 및 별칭이 가리키는 모델 시점이 함께 달라 정확도 2%p 차이의 원인을 하나로 분리할 수 없다.

다음 단계는 정답 정의와 제삼자 사기 언급의 처리 기준을 사람과 검토하고, 개선을 한다면 이 100건을 개발 자료로 전환한 뒤 별도의 새 평가셋으로 검증하는 것이다. 이번 작업은 재평가까지이며 서비스 탐지 프롬프트를 변경하지 않았다.
