# 문서 관리

기본 절차와 재개·기록 방법은 [공통 작업 흐름](workflow.md), 문서 위치 안내는 [AGENTS.md](../../AGENTS.md), 관련 문서 목록은 [Harness 인덱스](index.md)에 있다.

## 사실의 위치

| 종류 | 기준 위치 | 갱신하는 경우 |
|---|---|---|
| 사용자 제공 목적·범위·확정 방향 | [프로젝트 컨텍스트](../project-context.md) | 사용자가 방향을 추가·변경했을 때 |
| 현재 구현과 책임 경계 | `docs/architecture/` | 실제 구성·동작이 바뀌었을 때 |
| 구현할 구조와 인터페이스 | `docs/design/` | 해당 설계나 계약이 바뀌었을 때 |
| 선택의 이유와 상태 | `docs/decisions/` | 결정 제안·채택·대체가 있을 때 |
| 조사·실험의 근거 | `docs/analysis/` | 조사·실험 결과를 남길 때 |
| 변경 목적·요구·설계 | `openspec/changes/<change-name>/proposal.md`, `spec.md`, `design.md` | 해당 변경의 범위·요구·방법이 바뀌었을 때 |
| 변경 진행·검증·인계 | change의 `tasks.md`, `work.md` | 현재 작업의 진행과 결과가 바뀌었을 때 |
| 읽기 경로 | 각 `index.md` | 문서의 위치·역할·주요 상태가 바뀌었을 때 |
| 요구·설계·작업·검증의 연결 | 관련 본문의 관련 문서 항목과 change 문서의 직접 링크 | 기준 설계·관련 change·검증 근거의 연결이 바뀌었을 때 |

같은 계약이나 정책의 상세 본문을 여러 곳에 복사하지 않는다. 기준 문서 한 곳에 쓰고, 다른 문서에서는 필요한 요약과 링크로 연결한다. 인덱스는 문서를 찾는 지도이며 설계 본문의 대체물이 아니다.

AGENTS.md는 구현 전·중·후 각 단계의 핵심 행동과 문서·스킬의 사용 시점을 안내한다. 세부 절차·재개 방법·기록 크기·검증 명령은 harness/workflow.md에서 관리한다. 세부 항목을 루트에 모두 복사하지 않으며, 공통 흐름을 변경할 때는 두 안내의 단계와 책임이 일치하도록 맞춘다. OpenSpec은 변경별 목적·요구·방법·진행·근거·다음 행동을 구분한다.

change의 proposal·spec·design에서 관련 상위 설계와 기준 문서를 직접 연결한다. tasks는 완료 근거가 있는 work로, work는 관련 설계·변경 파일과 실제 검증 근거로 연결한다. 설계 본문의 관련 문서 항목에도 해당 change를 연결해 양쪽에서 찾을 수 있게 한다.

## 도구별 진입점과 공유 원본

공통 작업 안내는 AGENTS.md, 스킬 지침과 스크립트는 `.agents/skills/`에서 관리한다. [CLAUDE.md](../../CLAUDE.md)는 AGENTS를 import하고 Claude Code의 호출 방법만 안내한다. `.claude/skills/<skill-name>`은 해당 `.agents/skills/<skill-name>` 폴더를 가리키는 상대 심볼릭 링크다. 원본을 수정하면 두 도구가 같은 내용을 사용한다.

스킬을 추가·이동·삭제하면 Claude의 연결과 README의 호출 안내도 맞춘다. 심볼릭 링크가 보존되지 않는 환경에서는 CLAUDE에 연결한 원본 SKILL.md를 직접 읽어 적용한다. Codex용 `agents/openai.yaml`은 Codex UI 메타데이터이며 공통 절차는 SKILL.md에 둔다.

## 문서 상태

- 설계: `초안` 또는 `확정`. 확정의 근거를 적는다. 확정 설계도 구현 완료를 뜻하지 않는다.
- 결정: `제안`, `채택`, `대체`. 대체된 결정은 새 결정으로 연결한다.
- Change: `진행 중`, `완료`, `보류`. 상태는 openspec/index와 tasks에 맞추고, 완료는 해당 change의 인수조건과 검증에만 적용한다. work에는 실행한 근거를 남긴다.
- 아키텍처: `현재 구현`, `합의된 방향`, `미확정`을 구분한다.
- 분석: 조사 시점·실험 조건·결과·한계를 명시한다.

현재 코드와 문서가 다르면 관찰된 차이를 기록하고, 구현이 잘못된 것인지 문서가 오래된 것인지 판단한다. 코드를 문서에 적었다는 이유로 승인된 설계로 바꾸거나, 승인되지 않은 문서를 근거로 코드를 자동 변경하지 않는다.

## 파일과 인덱스

파일명은 역할이 드러나는 안정적인 이름을 사용한다. 같은 주제의 사소한 수정마다 `v0.1`, `v0.2` 사본을 쌓지 않고 Git 이력을 활용한다. 신규 하위 주제가 실제로 필요할 때만 폴더와 인덱스를 추가한다.

`docs/index.md`는 문서 종류별 역할과 진입점을 안내한다. 세부 주제·문서 목록과 각 본문의 내용 설명은 해당 폴더의 `index.md`에서 관리한다. 기능 동작·계약의 상세 설명은 본문에 작성하고, 변경 진행 상태는 OpenSpec에 기록한다.

`docs/`의 각 Markdown 문서는 같은 폴더의 `index.md`에서 제목·내용 설명과 상대 링크로 등록한다. 새 하위 `index.md`는 바로 상위 인덱스에서 연결한다. 문서 종류나 진입점이 바뀌면 `docs/index.md`와 필요한 경우 AGENTS.md도 맞춘다. 기존 폴더 안에 세부 문서를 추가하는 경우에는 그 폴더의 인덱스를 갱신한다.

OpenSpec change는 참고 저장소처럼 다섯 문서를 한 폴더에 둔다. `openspec/index.md`에서 각 change와 다섯 문서를 직접 링크하고 범위·상태를 안내한다. 각 change에 별도 index 파일을 추가하지 않는다. 선택적으로 추가한 검토·실험 문서도 openspec/index에 등록한다.

작성하지 않은 문서는 인덱스에 설명과 작성 예정 파일명을 텍스트로 적을 수 있지만 존재하는 파일처럼 링크하지 않는다. 템플릿은 작성에 필요한 항목만 선택하며 빈 설계 본문을 대량 생성하지 않는다.

## 동기화의 의미와 검사 범위

[문서 동기화 스킬](../../.agents/skills/scamshield-docs-sync/SKILL.md)은 변경된 사실을 식별하고 관련 기준 문서·작업 기록·인덱스를 갱신한다. 백그라운드에서 자동 실행되는 서비스나 Hook은 아니다. 작업 수행 중 에이전트가 스킬을 적용한다.

검사 스크립트는 로컬 링크의 대상 경로, docs·openspec의 인덱스 등록과 change의 다섯 필수 파일을 확인하는 읽기 전용 도구다. 외부 URL, 제목 앵커와 본문의 의미상 정합성은 검사하지 않는다. 코드 블록 안의 예시 링크는 제외한다. 내용의 중복·충돌·구현과의 불일치는 에이전트가 변경 범위와 실제 근거를 읽고 확인한다.
