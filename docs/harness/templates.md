# 기록 양식

필요한 문서를 작성할 때 아래 항목을 작업 크기에 맞게 사용한다. 모든 항목을 채우기 위한 가짜 내용이나 불필요한 새 문서를 만들지 않는다. 문서의 기준 위치와 상태는 [문서 관리](document-conventions.md), 전체 위치는 [Harness 인덱스](index.md)에 있다.

## 상세 설계

```markdown
# 주제

상태: 초안 / 확정
근거: 사용자 결정 또는 관련 결정 문서

## 목적과 범위
## 구조와 책임
## 입력·출력·상태 갱신
## 정상 흐름과 종료·실패 처리
## 검증할 동작
## 미확정 사항
## 관련 문서
```

## 설계 결정

```markdown
# 선택의 이름

상태: 제안 / 채택 / 대체
결정 근거: 사용자 지시 또는 채택 기록

## 문제와 제약
## 선택
## 검토한 대안과 trade-off
## 영향과 적용 상태
## 관련 설계·분석·작업
```

## 분석과 실험

```markdown
# 조사 또는 실험 주제

조사 시점:
대상과 조건:

## 확인할 질문
## 방법과 재현 절차
## 관찰 결과와 근거
## 한계와 미확인 사항
## 관련 설계·결정
```

## OpenSpec change

변경별 폴더는 `openspec/changes/<change-name>/`로 만든다. 이름은 변경 내용을 드러내는 짧은 소문자·하이픈 형식으로 정한다. 아래 다섯 문서를 [OpenSpec 인덱스](../../openspec/index.md)에 등록한다. 사용자가 이미 요청한 작업에 새 승인 단계를 붙이지 않고, 미채택 설계는 제안으로 구분한다.

### proposal.md

```markdown
# 변경 목적과 범위

## 문제와 목표
## 범위와 제외 범위
## 완료 조건
## 관련 상위 설계와 change 문서
```

### spec.md

```markdown
# 변경 요구사항

## 충족해야 할 동작과 계약
## 정상·실패 조건
## 검증 가능한 완료 조건
## 관련 상위 설계와 기준 문서
```

### design.md

```markdown
# 변경 설계

## 기존 구조와 변경할 부분
## 책임·인터페이스·데이터 흐름
## 선택·대안·trade-off
## 미정 사항과 검증 방법
## 관련 상위 설계와 기준 문서
```

### tasks.md

```markdown
# 작업 목록

상태: 진행 중 / 완료 / 보류

- [ ] 요구와 설계를 확인한다.
- [ ] 범위 안의 변경을 수행한다.
- [ ] 관련 검증을 실행하고 work에 근거를 기록한다.
- [ ] 기준 문서·인덱스·관련 문서 링크와 change 상태를 맞춘다.
```

### work.md

```markdown
# 진행과 검증 기록

## 실제 완료 범위와 변경 파일
## 검증
| 명령 또는 확인 | 결과 | 근거·한계 |
|---|---|---|
## 남은 사항과 다음 행동
```

현재 상태는 tasks, 실제 실행과 근거는 work에 구분해 남긴다. 장기적인 공통 계약·설계는 docs/design의 기준 문서로 연결하고, change에는 이번 변경에 필요한 요구와 적용 방법을 적는다. 진행 기록이 길어질 때만 날짜별 항목을 추가한다.
