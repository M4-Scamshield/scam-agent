# 공통 작업 흐름

이 문서는 구현 전·중·후의 세부 작업 절차와 재개·기록 방법의 기준이다. [AGENTS.md](../../AGENTS.md)에서 각 단계의 핵심 행동과 필요한 문서·스킬을 확인하고, 세부 실행 기준은 이 문서를 따른다. 관련 문서는 [Harness 인덱스](index.md)에서 찾고, 작업에는 [scamshield-work-cycle](../../.agents/skills/scamshield-work-cycle/SKILL.md)을 적용한다.

## 구현 전

1. [AGENTS.md](../../AGENTS.md), [문서 지도](../index.md)와 이 절차를 읽고, 요청에 해당하는 문서 경로를 찾는다.
2. 새 작업은 관련 아키텍처·상세 설계부터 읽어 전체 기준을 이해한 뒤 [OpenSpec 인덱스](../../openspec/index.md)에서 관련 change를 확인한다. 관련 change가 있으면 proposal·spec·design의 목적·요구·방법과 tasks·work의 진행·검증 근거를 읽어 기존 작업과의 관계를 파악한다. 기존 작업의 재개는 해당 change의 tasks·work에서 완료 범위·검증·미해결 사항·다음 행동을 먼저 확인하고, proposal·spec·design과 연결된 아키텍처·상세 설계를 읽은 뒤 이어간다.
3. 두 경우 모두 필요한 설계 결정과 조사·실험 근거를 확인한다. 관련 설계가 아직 없으면 [프로젝트 컨텍스트](../project-context.md)의 확정 방향과 미정 사항을 출발점으로 삼는다.
4. 설계와 실제 코드·설정을 함께 확인한다. 설계에 적혀 있다는 이유로 구현됐다고 판단하지 않는다.
5. 단순하지 않은 변경은 현재 구조, 변경할 점, 영향 범위와 완료 조건을 정리한다. 확정 설계와 충돌하는 큰 변경은 문제·대안·trade-off를 제안으로 남기고, 사용자 채택 전에 기존 설계를 대체하지 않는다.

## 구현 중

6. 기존 구조를 우선 활용하고, 현재 요청과 MVP 범위에 필요한 변경부터 수행한다.
7. 미확정 schema·Provider·threshold를 확정된 사실로 취급하지 않는다. 구현 중 계약이나 범위가 달라지면 관련 설계·결정·작업 기록을 함께 맞춘다.
8. 기능 변경에는 해당 동작을 확인하는 테스트를 함께 다룬다. 여러 단계의 작업은 기존 change의 tasks·work에 진행·문제·다음 행동을 남기되, 작은 수정마다 새 change를 만들지 않는다.

## 구현 후

9. 관련 테스트·빌드 등 실제로 가능한 검증을 실행한다. 실행한 명령·결과와 실행하지 못한 항목·이유를 구분한다. 검증에서 실패가 발견되면 작업 범위 안에서 수정하고 관련 검증을 다시 수행한다. 현재 가능한 검사 명령은 아래와 [README](../../README.md)에 있다.
10. [문서 동기화 스킬](../../.agents/skills/scamshield-docs-sync/SKILL.md)을 적용해 변경된 사실을 관련 아키텍처·설계·결정·작업 기록에 반영한다. 새 문서와 읽기 경로는 각 인덱스에 등록하고, 본문과 change의 관련 설계·작업·검증 링크를 맞춘다. 영향이 없는 문서는 수정하지 않는다.
11. change의 tasks에 실제 완료 범위를, work에 변경 파일 또는 설계 링크·검증 근거·남은 문제·다음 행동을 반영하고 openspec/index의 상태도 맞춘다. 검증하지 않은 기능을 완료로 표시하지 않는다.
12. 사용자에게 변경 결과, 주요 검증, 갱신한 문서와 미확정 사항을 간결하게 보고한다.

설계·문서 작업도 위 순서의 읽기·변경·검증·인계를 적용하되, 해당하지 않는 코드 구현·서비스 테스트를 요구하지 않는다. 다음 세션은 대화를 재구성하는 대신 문서 지도와 작업 기록에서 이어갈 수 있어야 한다.

## 이전 작업을 이어갈 때

이미 수행한 작업을 처음부터 반복하지 않는다. 현재 파일과 새 요청에 맞춰 기록을 이어가고, 사용자가 이미 내린 결정을 다시 승인받지 않는다. 다른 세션이 남긴 설계와 체크 표시는 실제 파일·검증 근거와 함께 확인한다.

## 작업 기록의 크기

단순 조회나 작은 수정에 장문의 계획·새 change를 요구하지 않는다. 여러 단계에 걸치거나 계약·동작·구조가 바뀌는 작업은 [양식](templates.md)을 참고해 openspec/changes 아래에 proposal·spec·design·tasks·work를 구성하거나 기존 change를 이어간다. 변경과 각 문서는 openspec/index에 등록한다.

공통 계약·설계의 상세 본문은 docs/design에 두고, 이번 변경에 필요한 부분과 적용 방법만 change의 spec·design에 적어 기준 문서로 연결한다. 진행과 실행 근거는 change의 tasks·work에 남기고, 관련 설계 본문의 관련 문서 항목에서 해당 change를 연결한다.

## 현재 검증 명령

현재 실행 가능한 공통 검사는 다음과 같다.

```sh
python3 .agents/skills/scamshield-docs-sync/scripts/check_docs.py
```

서비스 실행·빌드·테스트 명령은 아직 없다. 실행 환경을 구성할 때 [README](../../README.md)에 실제 명령을 추가하고 그때부터 작업에 맞게 사용한다.
