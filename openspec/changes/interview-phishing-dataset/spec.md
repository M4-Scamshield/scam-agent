# 합성 데이터 요구

- 한국어 면접 사칭 사기 통화가 정확히 100건이고 ID가 고유하다.
- 통화마다 `나`·`피싱범` 두 화자만 등장한다. 다른 인물을 언급할 수 있지만 세 번째 화자의 발화를 추가하지 않는다.
- 통화마다 50~100문장이며 발화 항목 하나가 문장 하나다. 50~100의 모든 정수 길이를 포함하고 문장 번호가 연속된다.
- 20개 사기 유형과 100개 직무·경력 사례를 사용하며 명시적 요구의 시작 위치와 지원자의 최종 반응을 기록한다.
- UTF-8 JSON 원본과 평가 입력을 실제 파일로 제공한다. 평가 입력은 A/B 화자와 문장만 포함하고 원본과 같은 ID로 연결한다.
- 원본 화자 역할과 정답은 평가 모델 입력에서 제외한다. 모델 결과나 실제 피해 결과를 생성한 것으로 표시하지 않는다.
- 동일 대화·통화 내 동일 문장·자리표시자·실사용 연락처와 URL 형태를 검사한다. 통화 간 문답 공유는 허용하되 집계와 한계를 공개한다.

## 후속 정상 표본과 실제 평가

- 정상 면접 통화 100건을 추가하고 `label: normal`, `나`·`면접관`으로 구분한다. 기존 사기 원본은 바꾸지 않는다.
- 정상과 사기 각각의 직무·경력·길이를 통화별로 맞추고 20개 주제·5개 종료 경로를 작성한다. 정상 근거 배열은 비우고 최초 사기 근거는 null로 둔다.
- 혼합 200건의 순서를 섞고 중립 ID와 A/B만 모델 입력에 포함한다. 정답·대응 통화는 별도 파일에 저장한다.
- 기존 `Plan1-JevOnly`의 전체 transcript 1회 판단·공통 탐지 프롬프트·choice Yes/No를 사용한다. 실제 verdict로 TP/FP/TN/FN을 집계하고 성공·실패 수와 주요 지표를 보고한다.
- 기존 KorCCVi 결과는 덮어쓰지 않고 `results/interview_200/`에 결과표·예측·confusion matrix 이미지를 둔다. 모델 응답 버전을 기록하지 못했다면 설정 별칭만 알 수 있다고 명시한다.

정확한 필드·사용법은 [사기 데이터셋 계약](../../../datasets/interview_phishing/README.md)·[정상·혼합 평가셋 안내](../../../datasets/interview_normal/README.md), 실제 검사 근거는 [work](work.md), 서비스 입력의 기존 범위는 [mvp-flow](../../../docs/design/mvp-flow.md)를 따른다.

## 새 대본 평가 요구 (2026-11-14)

- 사기·정상 각 50건의 별도 면접 대본을 작성하고 기존 200건의 문답을 복사하지 않는다. 정규화한 전체 대화 및 15자 이상 발화의 기존 자료 정확 일치를 검사한다. 의미적 독립성이나 모델 사전학습 미포함은 이 검사로 증명하지 않는다.
- 각 클래스에서 8발화 20건·10발화 20건·12발화 10건, 면접관 A/B 각 25건으로 길이와 화자 대응을 맞춘다. 정답 근거는 모델 입력과 분리한다.
- 라벨과 SHA-256을 호출 전에 고정하고 예측 확인 후 대본·라벨·프롬프트·판정 기준을 조정하지 않는다. 기존 Plan1의 API choice를 그대로 집계하고 실패는 별도 표기한다.
- 새 표본의 혼동행렬·정확도·정밀도·재현율·F1·특이도 및 오류 목록을 남긴다. 독립 사람 검수나 실측 모집단 성능으로 표현하지 않는다.

형식은 [새 대본 안내](../../../datasets/interview_holdout/README.md), 결과와 검증은 [work](work.md)를 따른다.
