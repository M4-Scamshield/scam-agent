# 분석 실패 대응 요구 초안

상태: 초안(사용자가 제시한 화면 상태·최대 재시도 3회·전체 문맥 판단·근거 필터링 방향 반영, 상세 계약과 구현은 미완료). 현재 실행 계약과 구현 전 방향은 [통화 계약](../../../docs/design/state-and-graph.md)에 구분한다.

## 충족해야 할 동작과 계약

1. 분석이 실패한 요구를 정상으로 확인한 요구와 구분해 호출자에게 전달한다. 실패를 이유로 사기를 확정하지 않는다.
2. 이전 위험 판단과 확보한 flagged 도구 근거는 후속 분석 실패로 잃지 않는다.
3. 실패한 상태·근거·오류·시도 정보를 남겨 새 대사에서 같은 상태가 Yes가 되지 않아도 복구할 수 있어야 한다.
4. 복구는 원인에 맞게 제한한다. timeout·연결·429·5xx, 출력 오류, 인증·요청 설정 오류를 구분하고 무한 재시도하지 않는다.
5. 위험 판단과 분석 완료 여부의 출력·저장 계약, 사용자 임시 안내와 알림 정책을 구분한다. 기존 상태·점수 소비자에 미치는 영향을 확인한다.
6. 진단에는 단계·오류 코드·시도·시간·입력 크기를 사용할 수 있지만 API 키·인증 정보·대화 원문은 노출하지 않는다.
7. 최초 분석과 재시도 중에는 화면에 `분석 중`을 유지한다. 최대 3회 재시도한 뒤에도 실패하면 해당 구간을 `분석 실패`로 표시하고 무기한 진행 상태로 남기지 않는다. 횟수는 최초 시도 외 추가 3회로 해석하며, 상태별·단계별 적용과 중복 요청 시 예산 처리는 상세 설계에서 정한다.
8. 실패한 분석은 기존 전체 대화 맥락을 보존해 다시 실행한다. 성공한 결과와 미완료 작업을 구분하며 재시도 때문에 새 발화를 잃거나 같은 발화를 이력에 중복 추가하지 않는다.
9. 최종 위험 판단의 입력은 전체 대화다. 결과의 근거는 실제로 판단을 뒷받침하는 발화를 선택한다. 새 줄 묶음을 그대로 최종 근거로 복사하지 않는다.
10. 후보 감지 범위·재시도 범위·최종 근거 범위를 구분한다. 입력에 없는 발화 번호를 근거로 채택하지 않고, 이전 대화 근거도 원래 번호로 추적할 수 있는 계약을 마련한다.

## 정상·실패 조건

- 성공한 분석은 기존 위험·점수 규칙을 유지한다. 이번 개선과 무관한 정책을 함께 바꾸지 않는다.
- 일부 상태만 실패하면 성공한 결과를 유지하면서 미완료 범위를 드러낸다.
- 모든 상태가 실패해도 정상으로 확인됐다는 의미가 되지 않아야 한다.
- 인증·설정 오류는 운영 수정이 필요한 오류다. 자동 재시도의 성공을 전제하지 않는다.
- 재시도 중 `분석 중`, 소진 후 `분석 실패` 방향은 사용자 제안으로 반영했다. 서버와 agent 중 실행 책임, 단계별 예산, 총 대기·간격과 세부 문구는 설계 단계에서 정한다.

## 검증 가능한 완료 조건

- F1 Yes 후 timeout·연결·429·5xx·출력 오류 각각에 대해 정상 오인을 방지한다.
- 다음 요청에서 F1 No여도 미완료 작업을 복구할 수 있다.
- 다른 상태의 성공 결과와 이전 위험을 유지한다.
- flagged 도구 결과 후 모델 마무리 실패에도 위험 근거를 유지한다.
- 재시도 한도·소진·오래된 요청 재전송·state JSON 왕복을 검증한다.
- 정상 성공 경로와 기존 import·Supervisor 연결의 호환성을 확인한다.
- 로그에 대화 원문이나 인증 정보가 없는지 확인한다.
- 분석 중 → 실패 → 재시도 → 성공 또는 소진의 진행 상태와 이전 위험 유지 여부를 검증한다.
- 재시도 중 새 발화 도착과 중복 요청이 기존 작업을 누락하거나 재시도 예산을 무한 초기화하지 않는지 확인한다.
- 묶음 입력에서 실제 요구와 단순 응답을 구분하고, 문맥을 보존하면서 최종 근거를 선택하는지 확인한다.
- 근거 번호의 원문 대응, 화자·인용·부정 표현, 이전 대화 근거, 근거가 없는 모델 출력을 검증한다. 단순히 키워드가 있다는 이유로 위험 근거를 확정하지 않는다.

위 조건은 후속 구현의 초안이며 이번 문서 작업의 테스트 통과를 의미하지 않는다.
