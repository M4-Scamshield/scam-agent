# 분석 실패 대응 요구사항

상태: 2026-11-28 사용자 구현 요청에 따라 agent 범위 구현. 공통 계약은 [State·Graph](../../../docs/design/state-and-graph.md), 실제 검증과 미연결 범위는 [work](work.md)에 있다.

## 충족해야 할 동작과 계약

1. 최종 판단은 전체 대화를 읽고, 직접 위험 근거와 보조 맥락의 발화를 별도로 선택한다. 새 발화 묶음 전체를 근거로 복사하지 않는다.
2. 원래 발화 seq를 보존한다. 문자열 이력은 저장된 원문 지문·번호 대응으로 복원하고, 번호가 없는 과거 이력의 seq를 추측하지 않는다. 이력 불일치는 입력 오류다.
3. 실패한 통화 감지 또는 상태별 분석만 최초 시도 외 최대 3회 추가 재시도한다. 성공한 다른 상태·원문 추가는 반복하지 않는다.
4. 진행 콜백에 분석 중을 전달하고, 전체 작업 종료 시 완료 또는 실패를 한 번 전달한다. Supervisor는 통화 내부의 완료 이벤트를 자신의 작업 종료 전에 내보내지 않는다.
5. 소진·영구 오류는 analysis_status=failed와 정해진 실패 코드를 반환한다. risky가 없다면 status·score는 None이며 정상 0점으로 해석하지 않는다.
6. 기존 위험과 검증된 flagged 도구 근거는 모델 마무리 실패에도 유지한다. 도구는 해당 상태에 허용되고 실제 발화에서 확인한 값만 조회한다.
7. 소진된 실패는 state에 보존한다. 다음 단순 응답·채팅 재전송이 이를 숨기거나 예산을 초기화하지 않는다.
8. 실패 정보·진행 이벤트·로그에 API 키·인증 정보·대화·원시 예외 메시지를 노출하지 않는다.

## 정상·실패 조건

- timeout·연결·429·5xx·출력·근거 오류는 0.5·1·2초 간격으로 재시도한다.
- 인증·요청 거부·설정 오류와 알 수 없는 내부 오류는 즉시 최종 실패다.
- 잘못된 근거 번호·근거 없는 risky는 성공으로 채택하지 않는다. 단순 맞장구는 코드에서도 직접 근거에서 제거한다. 모델이 선택한 내용의 의미상 정확성을 코드가 완전히 보장하는 것은 아니다.
- 같은 상태의 새 분석이 전체 문맥을 보고 성공하면 그 상태의 이전 실패를 해소한다. 이전 Jev 감지 실패는 다른 구간의 감지 성공만으로 없애지 않는다.
- 후보 감지 창·F3/F5 보류·risky 고정·점수 감쇠·URL 판정은 이번에 변경하지 않는다.

## 검증 가능한 완료 조건

- 근거 선택·단순 응답 제외·원래 번호·JSON 왕복·이력 유실/변조·잘못된 근거 거부.
- 같은 전체 입력을 최대 4회 시도하고 다른 성공 상태를 반복하지 않는지 확인.
- 일시 오류 소진, 영구 오류 즉시 실패, 콜백 전달 실패의 격리.
- 이전 위험·도구 근거·과거 미분석 구간의 실패 기록 유지.
- Supervisor의 중복 채팅·진행 종료 순서와 CLI의 분석 중/재시도/실패 표시.
- 기존 통화·URL·CLI·그래프 exporter 회귀 검증.

실제 BE 이벤트·프론트 표시·모델 선택 정확도·운영 지연 검증은 후속 범위다.
