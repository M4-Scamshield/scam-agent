# 분석 실패 시 정상 오인 방지와 복구

상태: 진행 중(agent 구현·회귀 검증 완료, 별도 BE·프론트 연결·실제 모델 검증은 후속).

## 문제와 목표

상태별 Haiku 분석이 실패하면 해당 상태를 생략하고 정상 0점으로 응답할 수 있다. 실패한 요구를 보관하지 않아 같은 상태가 다시 Yes가 될 때까지 재평가하지 않는다. 사용자는 2026-11-28 첫 번째 핵심 위험부터 해결하기로 하고, 브랜치를 만들어 문제를 docs에 정리하도록 요청했다.

실패를 정상 확인으로 오인하지 않게 하고, 확보한 위험 근거를 지키면서 미완료 분석을 복구하는 것이 목표다. 현재 정책과 재현 근거는 [기능상 위험 검토](../../../docs/analysis/runtime-risk-review.md)에 둔다.

후속 대화에서 사용자는 재시도 중 분석 중 유지·최대 3회 재시도·소진 시 분석 실패 표시와 전체 대화 기반 판단·근거 필터링을 요구했다. 이어 이 브랜치에서 합의한 내용만 구현하고 작은 커밋으로 나눠 push하도록 요청했다. 현재 구현 계약은 [State·Graph](../../../docs/design/state-and-graph.md)에 있다.

## 범위와 제외 범위

- 이번 문서 단계: 핵심 위험 목록, R1 실패 원인·timeout 설정·재현, 사용자 후속 방향·미정 사항·후속 인수조건.
- 구현 범위: agent의 진행 상태·최대 3회 재시도·실패 보존, 이전 위험·도구 근거 보존, 전체 문맥 재분석과 근거 선택, Supervisor·CLI 전달.
- 제외: 다른 위험의 일괄 수정, F3·F5 보류·risky 고정·점수 감쇠 정책의 자동 변경, 실제 조회 API 도입, BE·UI·배포 환경 수정.
- 최초 시도 외 최대 3회 추가 시도, 0.5·1·2초 대기, 영구 오류 즉시 실패와 nullable 위험도·점수를 agent에 적용했다. 실제 화면·이벤트 전송과 서버 대기/임대 조정은 후속이다.

## 완료 조건

- 문서 단계: 관찰·대역 재현·미측정 사항과 제안을 구분하고 관련 기준 문서·인덱스·인계 기록을 연결한다.
- agent 구현: [요구](spec.md)의 코드·회귀 검증·문서 반영을 완료한다. 별도 BE·프론트와 실제 모델 검증까지 완료한 것으로 표시하지 않는다.
