## 2026-11-28 후속 방향과 발화 근거 확인

사용자는 실패한 분석에 대해 기존 대화를 다시 분석하고, 프론트의 `분석 중`을 유지하며 최대 3회 재시도 후 소진하면 `분석 실패`를 표시하자는 방향을 제시했다. 이어 전체 기존 대화를 바탕으로 분석하고, 새 발화 전체를 근거로 삼지 말고 필터링해야 한다고 명시했다.

[프로젝트 컨텍스트](../../../docs/project-context.md)와 [통화 계약](../../../docs/design/state-and-graph.md)에 사용자 방향과 현재 미구현 상태를 기록하고 change의 목적·요구·설계·작업과 분석·인덱스를 맞췄다. 재시도 3회는 최초 시도 외 추가 3회로 해석해 초안에 적었다. 단계별 예산·실행 주체·간격·총 대기·인증 오류 예외·최신 맥락 반영은 미정이다.

추가 일회성 대역 실행에서 F1 Yes와 risky 판단을 고정하고 seq 101 기관 소개·102 응답·103 송금 요구를 한 묶음으로 전달했다. 현재 출력은 `evidence_seqs=[101,102,103]`, Haiku 입력은 `detected_lines=[1,2,3]`이었다. 이는 최종 근거를 선택하지 않고 요청 묶음 전체를 기록한다는 제어 흐름의 재현이다. 실제 모델의 근거 선택 정확도 실험은 아니다.

최종 판단용 전체 대화, 감지 후보, 재시도할 작업, 최종 근거를 구분하고 이전 발화의 원래 seq 보존이 필요함을 [분석](../../../docs/analysis/runtime-risk-review.md)과 [설계](design.md)에 정리했다. 제품 코드·BE·프론트는 변경하지 않았다.

후속 검증: 전체 작업 트리 문서 검사는 기존 미등록 11건으로 동일하게 실패했다. 추적 파일과 이번 신규 6문서를 임시 복사한 범위 검사에서는 문서 60개·로컬 링크 789개·오류 0개로 통과했다. `git diff --check`도 통과했고, 현재 실행·사용자 방향·세부 제안·미구현 상태를 본문에서 구분했다. 제품 코드 변경이 없어 기존 서비스 테스트를 반복 실행하지 않았다.

## 2026-11-28 agent 구현과 커밋

사용자는 이 브랜치에서 합의한 범위의 코드만 구현하고 커밋을 작게 나눠 push하도록 요청했다. 별도 BE·프론트 저장소까지 수정할지 범위를 물었으나 응답이 없어 현재 저장소의 agent·진행 계약·CLI 범위로 진행했다. 별도 저장소와 원래 데이터·실험 파일은 수정하지 않았다.

구현은 [현재 통화 계약](../../../docs/design/state-and-graph.md)과 [적용 설계](design.md)에 반영했다. 전체 대화와 원래 seq를 보존하고 직접/보조 근거를 선택한다. 각 실패 작업만 최초 시도 후 3회 추가 재시도하며 성공 상태·원문을 반복하지 않는다. 최종 실패를 정상 0점으로 반환하지 않고 진행 콜백·실패 기록을 전달한다. 기존 위험과 원문에서 확인한 flagged 도구 근거도 유지한다. 후속 감지 성공만으로 과거 미분석 구간의 실패가 사라지지 않게 회귀 검증했다.

## 남은 사항과 다음 행동

1. 현재 계약·인계 문서의 후속 커밋도 같은 브랜치에 push하고 최종 HEAD의 원격 반영을 확인한다.
2. 별도 BE·프론트의 진행 이벤트와 표시, HTTP timeout과 작업 임대 시간을 연결한다. 실제 화면까지 구현 완료로 표시하지 않는다.
3. 실제 모델의 근거 선택 품질·인용/부정·장시간 통화·지연을 검증한다. 번호 존재 검사만으로 의미상 정확성을 보장하지 않는다.
4. 다른 위험은 후속으로 다룬다. F3/F5 보류·risky 고정·점수 감쇠·혼합 URL 라우팅은 이번에 변경하지 않았다.
5. 기존 미등록 문서 11건은 원래 작업에서 정리한다. 이번 변경의 검증과 전체 작업 트리의 기존 오류를 구분한다.
