# 진행과 검증 기록

## 2026-11-15 설계 제안

- 경위
  - [KorCCVi 수법 분석](../../../docs/analysis/korccvi-scam-tactics.md)으로 R1~R9와 NEW 수법을 대화 특징 6개(F1~F6)로 다시 묶었다.
  - 사용자는 다음 방향을 제시했다.
    - 이 6개를 Jev가 판단하는 상태로 만든다.
    - 관찰·주의·경고 단계는 쓰지 않는다.
    - 켜진 상태에 맞는 에이전트를 부른다.
    - 대응은 전역 문구가 아니라 LLM이 지금 대화를 보고 최종 판단해 쓴다.
  - 이 방향에 다음 두 가지를 더해 [spec](spec.md)과 [design](design.md)에 제안으로 기록했다.
    - 절대선: LLM이 정상으로 판단할 수 없는 요구
    - 판단 근거 제한: 상대가 주장한 신분·절차는 근거로 쓰지 않는다
- 데이터 근거(KorCCVi 사기 694통화, 판단불가 제외, LLM 라벨, 사람 검수 없음)
  - 상태별 출현율(괄호는 첫 등장 상대 위치 중앙값)
    - F1 20.5% (0.28)
    - F2 35.6% (0.30)
    - F3 18.4% (0.53)
    - F4 78.1% (0.20)
    - F5 39.5% (0.37)
    - F6 83.4% (0.03)
  - 특징이 2개 이상인 통화는 608건(88%)이다.
  - 이 수치는 기존 라벨을 F 묶음에 다시 배정해 낸 것이다. 재배정 스크립트는 아직 저장소에 없고, 대화 중 임시로 실행했다.
- 아직 실행하지 않은 것
  - 코드 변경
  - Jev 실제 호출
  - 평가

## 2026-11-16 팀장 협의와 이슈 등록

- 사용자가 팀장과 이 구조로 전환하기로 협의했다. 상태별 LLM은 Claude API 에이전트로 쓰고, 판단 결과별 점수를 매긴다.
- F1은 복잡하지 않게 하기로 했다. LLM 호출 1번과 사기계좌 조회 tool 하나, 확인 질문 3개로 구성한다([design](design.md)의 F1 간단 구성).
- 작업 이슈 [#13](https://github.com/M4-Scamshield/scam-agent/issues/13)을 등록했다.
- 코드 변경, Jev 실제 호출, 평가는 아직 하지 않았다.

## 2026-11-16 미정 사항 결정

- 사용자가 [design](design.md#결정-사항-2026-11-16-사용자-결정)의 결정 사항을 정했다.
  - `voice_phishing` 질문은 당분간 남기되 나중에 없앤다. 없애는 근거를 얻으려고 평가에서 "이 질문만 Yes인 사기"를 따로 센다.
  - 상태 에이전트만 Claude API로 만든다. BE 계약은 바꾸지 않고 상태 결과를 `OBSERVE/WARN`과 score로 바꿔 내보낸다.
  - 점수는 임시 값으로 시작한다. tool은 F1·F3용 Mock만 만든다.
- 남은 미정: Jev 기준값, 실제 tool API, F2 기준표
